# Android SDK 集成

简体中文 | [English](SDK.en.md)

Android 实现使用随包提供、未经修改的阿里云融合认证 SDK 1.2.16。厂商二进制文件仍受厂商条款约束；许可范围见包根目录的 [NOTICE](../NOTICE)。

随包提供的 SDK 制品通过包内的本地 Maven 仓库解析，其中包含 SDK 资源、Manifest 声明、供宿主使用的 ProGuard 规则和原生库，无需另行下载或配置本地文件系统的绝对路径。

对于使用 `flutter build aar` 分发的 Flutter add-to-app 项目，插件 AAR 保留了对 `dev.aliyunfusionauth.vendor:fusionauth:1.2.16` 的传递依赖。Flutter 生成的 Maven 产物不会复制本包的 `vendor` 仓库。请将该仓库与生成的 AAR 仓库一起分发，或将未经修改的 SDK 制品发布到 Android 宿主构建可访问的仓库。宿主需要同时配置这两个仓库，仅配置 Flutter 生成的仓库并不足够。此额外的 AAR 分发方式尚未经过构建验证。

| 制品 | SHA-256 |
| --- | --- |
| `fusionauth-1.2.16.aar` | `286efa126634c92da7fa0b6c22808ed8e27b7a485418ebdc2c4d64534ad33fc4` |

桥接代码使用 Android SDK 36 编译，支持 Android API 21 及以上版本。随包提供的原生库包含 `arm64-v8a`、`armeabi-v7a` 和 `x86`，不包含 `x86_64`。请在架构受支持、装有 SIM 卡且可使用移动数据的真机上验证认证流程。两个 ARM64 库均使用 16 KiB ELF 加载段对齐。

桥接层不包含也不初始化友盟组件，常规认证使用主 SDK。如果宿主 App 在云端策略中启用了依赖友盟的可选风控节点，必须自行集成相应的厂商组件、取得用户同意，并在认证前完成初始化。否则，请在云端策略中关闭这些可选节点。SDK 会在使用可选组件前检测它们是否存在；供宿主使用的混淆规则已考虑 Release 构建中缺少这些组件的情况。

每次认证调用都要求明确的用户同意、App 名称和两个 HTTPS 协议地址。桥接层保留一键认证页面中的运营商协议，并添加宿主 App 的协议。支持登录/注册（`100001`）和重置密码（`100003`）；重置密码还需要提供已有手机号。仅在显式调用认证时初始化 SDK。运营商认证失败后，会继续执行策略配置的下一节点，包括短信认证；切换号码不会被视为取消。SDK Token 过期时以 `token_expired` 结束本次认证，App 可从服务端获取新 Token 后重试。

认证返回不透明的 `verifyToken`。宿主服务端必须先调用阿里云接口验证该凭证，再执行登录、注册或重置密码。仅收到 SDK 成功回调并不代表已获授权。桥接层不会记录 Token 或手机号。取消、超时、Activity 分离和 FlutterEngine 分离都会清理当前会话及协议页面。

每次初始化新的 SDK 实例前，桥接层都会观察 SDK 1.2.16 的 `AlicomFusionSceneUtil.isHasFinish()` 标志，且不会阻塞主线程。这可以避免上一次短信 Activity 尚需在主线程完成销毁时，新的 SDK 构造函数进入忙等待。该行为依赖厂商内部实现，与随包 SDK 版本绑定；升级二进制文件时必须重新验证。等待可被取消，并受正常初始化超时限制。
