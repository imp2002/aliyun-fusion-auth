## 真机与服务端联调

| 测试 | 预期 |
| --- | --- |
| 未同意应用隐私告知 | 默认不初始化；仅登录显式启用 `deferConsentToNative` 可先取号，仍禁止未经勾选的登录或短信操作 |
| 首次打开原生认证页 | 应用名、协议链接正确；运营商协议保留；同意框不预先勾选 |
| 登录/注册 `100001` | 返回凭证后交后端核验，后端确认手机号才创建登录态 |
| 重置密码 `100003` | 必须传入目标；后端核验号码与保存的目标一致才授予重置权限 |
| 使用其他手机号完成认证 | 后端拒绝对原目标的密码重置，不接受客户端预填值作为证明 |
| 运营商路径不可用 | 按控制台方案进入可用的短信/其他后续节点，或返回最终失败 |
| 短信验证码错误、重发、超时 | 能纠正或结束；不会误判成业务成功 |
| Token 过期或无效 | 返回失败；使用后端新 Token 发起新的尝试 |
| 点击原生备用登录入口 | 原生会话结束后返回 `alternative_login`；应用打开对应登录页，不提交凭证；返回不自动重弹 |
| 点击返回、关闭、调用 `cancel()` | 当前 Future 结束，原生页关闭，可以再次发起 |
| 连续点击、认证中切换页面、前后台切换 | 无并发认证、悬挂 Future 或旧回调污染后续尝试 |
| 断网、弱网、SDK 无回调 | 失败或超时后可恢复，不授予业务权限 |
| 重放同一凭证、并发提交、已过期 attempt | 后端拒绝重复使用，不重复完成敏感操作 |
| 日志与错误监控 | 不包含 Token、AccessKey 或完整手机号 |

在实际目标运营商、SIM 和网络条件下验证；模拟器不能证明运营商取号成功。若启用额外风险/评分节点，还需单独验证其组件依赖、用户告知及服务端判断。演示程序只展示“取得凭证，须交服务端核验”，不能作为应用已登录的验证结论。
